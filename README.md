# 권용현 · HOURGLASS

크롬과 와이어프레임으로 재해석한 모래시계 포트폴리오. **한 화면에서 영화처럼** 재생되는
구조로, 페이지는 스크롤되지 않고 장(chapter)만 전환됩니다.

12장 · 84건의 기록 · 실제 입자 시뮬레이션으로 그려지는 모래시계 ·
그 시뮬레이션을 그대로 읽는 계기판.

```bash
npm install
npm run dev          # http://localhost:3000
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 정적 export → `out/` |
| `npm run verify` | typecheck → lint → 색상 검사 → build → 콘텐츠 감사 |
| `npm test` | 빌드 후 Playwright 43개 테스트 |
| `npm run audit` | 콘텐츠 감사 (번역 누락 · 미검토 문구 · 수치 재검증) |
| `npm run check:css` | 잘못된 색상 리터럴 검사 — 아래 *색상 검사* 참고 |
| `npm run og` | OG 카드 재생성 (`public/og.png`) |
| `npm run images` | 이미지 티어 재생성 — 아래 *이미지 파이프라인* 참고 |

## 계기판 — 이 사이트의 중심 장치

레퍼런스는 히어로 옆에 `MainLogo Quaternion` 실시간 수치를 띄워, 사이트가 자기 3D 객체의
상태를 스스로 읊게 합니다. 같은 장치를 **이 사이트가 실제로 시뮬레이션하는 것** 위에 올렸습니다.

```
SAND SYSTEM
FLOW   048     공중에 떠 있는 알갱이 수
FILL   0.45    이징된 충전율
TRGT   0.45    수렴 목표 (= 현재 장)
VOL    0.38    높이맵 총합, 구근 기준 정규화
ANG   60.5°    더미가 실제로 안착한 안식각
SRG    0.00    직전 컷 이후 남은 유량 서지
```

**여섯 값 모두 측정값입니다.** 장을 넘기면 FLOW가 치솟고 SRG가 1에서 감쇠하는 것이
보입니다 — 그게 시뮬레이션이지, 돌아가는 가짜 숫자가 아닙니다. 계기판이 거짓말을 하면
장치 자체가 거짓이 되고, 크롬을 두른 거짓말은 크롬이 없는 것보다 나쁩니다.

테스트가 이 점을 직접 검증합니다 (`tests/instrument.spec.ts`): 1초 사이에 최소 한 채널이
바뀌지 않으면 실패하고, 장을 넘겼을 때 TRGT가 커지지 않으면 실패합니다.

## 모래시계 = 실제 시뮬레이션

CSS 애니메이션이 아니라 매 프레임 계산되는 입자 시뮬레이션입니다
(`src/lib/sim/hourglass.ts`). SVG는 유리 용기만 그립니다.

- 알갱이가 목에서 방출 → 중력 낙하 → 기울어진 벽에 튕김 → 바닥 더미에 착지
- 더미는 84칸 heightmap. **안식각**을 넘으면 옆으로 흘러내려 원뿔이 만들어집니다
- 더미 총 부피가 현재 장으로 수렴 → 모래 높이가 곧 진행도
- 목 부분에 전기 블루 블룸 — 와이어프레임 공간의 빛이 통과하는 것으로 읽힙니다

### 고친 것

**프레임률 종속 (1차).** 원본은 위치를 *프레임당*, 중력을 *초당*으로 적분해서 120 Hz 화면에서
모래가 두 배 빠르게 떨어졌습니다. 전부 초당 단위로 환산했습니다.

**절반부터 흐름이 멈추던 문제 (3차).** 알갱이는 목 바로 아래에서 방출되고, 더미 표면보다
아래에서 생긴 알갱이는 첫 스텝에 착지한 것으로 처리됩니다. 물려받은 안식각이 약 56°였는데
이건 마른 모래가 설 수 없는 경사이고, 더미 원뿔의 꼭대기가 **약 60% 지점에서 목을 넘어섭니다.**
그 뒤로는 새 알갱이가 이미 더미 안에서 태어나 즉시 착지 — 12장 중 5장에서 모래시계가
**완전한 정지 화면**이었습니다.

아무도 몰랐던 이유는 아무도 재지 않았기 때문입니다. 계기판이 FLOW를 찍기 시작하자
사이트 절반에서 `000`이 나왔습니다.

안식각을 마른 모래의 실제 값인 34°로, 충전 계수를 0.74로 내려서 가득 찬 상태에서도 낙하
거리가 남도록 했습니다. 흐름이 채워질수록 가늘어지되 멈추지는 않습니다 — 실제 모래시계와
같습니다. 계기판의 ANG 값도 이제 물리적으로 말이 되는 숫자를 읽습니다.

회귀 테스트가 이 버그를 직접 잡습니다 (`tests/instrument.spec.ts` — "the pour never stalls").
옛 값으로 되돌리면 `chapter 7 (fill 0.63) has no grains in flight`로 실패하는 것을
확인했습니다.

## 장면 구성 (12장)

| # | 장 | 내용 |
|---|---|---|
| 01 | 표제 | 이름 · 헤드라인 |
| 02 | 인물 | 소개 · 태그 · 수치 요약 · 대표 성과 6건 |
| 03 | 원칙 | 모래알 우선순위 — 시급성 × 중요도 4분면 |
| 04 | 연대기 | 학력 3건 + 경력 5건 |
| 05 | 역량 | 5개 도메인 · 81개 스킬, 근거 건수 포함 |
| 06 | 지표 | 연도별 산출 · 수상 등급 분포 · 역량 증명 깊이 |
| 07 | 수상 | 포커스 패널 + 상장 35건 (7×5) |
| 08 | 작업 | 포커스 패널 + 프로젝트 35건 (7×5) |
| 09 | 자격 | 자격증 5건 |
| 10 | 분석 | SWOT 4사분면 |
| 11 | 지향 | 일하는 기준 3가지 + 지원 목표 |
| 12 | 엔딩 | 인용구 · 링크 |

장 번호·이름·고스트 단어는 전부 `CHAPTERS` 배열 순서에서 자동으로 나옵니다.

**숫자는 하나도 하드코딩되어 있지 않습니다.** "수상 35건"은 `awards.length`이고, 등급 범례는
group-by이며, 역량 칩의 숫자는 그 태그를 실제로 가진 작업 수입니다.

### 06 지표

세 패널 모두 84건의 기록에서 렌더 시점에 집계합니다. **불리한 숫자도 같이 싣습니다** —
"태그 90개 중 69개가 단 1건". 데이터에서 가장 약한 사실이고, 이걸 수상 건수 옆에 놓는 것이
수상 건수를 믿을 이유가 됩니다.

색은 눈대중이 아니라 검증했습니다. 이번 팔레트는 **여섯 검사를 전부 통과**합니다 —
금색 시절에는 단일 색상 2단계 인코딩이라 명도 밴드 검사를 구조적으로 통과할 수 없어
예외를 문서로 남겨야 했는데, 크롬 팔레트는 밴드 안에 채도를 갖춘 두 번째 색상(틸)이
있어서 그럴 필요가 없어졌습니다. 검증 기록은 `src/data/charts.ts` 주석에 있습니다.

수상 등급 색도 같은 검증된 램프에서 나옵니다 — 타일·배지·막대가 전부 한 램프를 씁니다.

## 접근성

- **`prefers-reduced-motion`** — 배경 모래·와이어프레임 복도·스캔라인 루프가 *정지*하고
  (숨기는 게 아니라 루프를 돌리지 않습니다), 켄번즈와 자동재생이 꺼집니다. 남는 것은
  사용자가 직접 요청한 장면 전환뿐입니다. 전용 테스트 6개가 이 경로를 검증합니다.
- **키보드** — 벽 타일 35개를 방향키로 이동(열 수는 실제 렌더 기하에서 측정), dossier는
  실제 focus trap + 포커스 복원, 닫힌 시트는 `inert`.
- **스크린리더** — 장이 바뀌면 `aria-live`가 번호와 이름을 읽습니다. 차트에는 같은 숫자를
  담은 실제 `<table>`이 `aria-describedby`로 연결되어 있습니다. 계기판은 `aria-hidden`
  입니다 — 초당 8번 바뀌는 여섯 숫자를 읽어주면 페이지를 쓸 수 없게 됩니다.
- **언어** — 미번역 영어 필드는 한국어를 보여주되 `lang="ko"`를 붙입니다.

## 배포

정적 export이므로 서버가 없습니다. `out/`을 어디에 올려도 동작합니다.

### GitHub Pages

Pages는 켜져 있고, 주소는 https://yhkwon2004.github.io/portfoli/ 입니다.

배포 워크플로가 둘 있습니다. 하는 일이 겹치므로 어느 쪽을 남길지는 정리 대상입니다.

| 파일 | 트리거 | 비고 |
|---|---|---|
| `nextjs.yml` | 이 브랜치에 push | GitHub의 Next.js 샘플. **현재 배포되는 쪽** |
| `deploy.yml` | `main` push · 수동 실행 | 직접 쓴 것. `main` 이 없어 지금은 수동 실행만 |

둘 다 `concurrency: pages` 라 동시에 돌지는 않지만, 같은 사이트를 두 워크플로가 만드는
상태는 오래 두면 어느 빌드가 올라갔는지 알기 어려워집니다.

**하위 경로 주의.** Pages는 프로젝트 사이트를 `/portfoli` 아래에서 서빙합니다.
`configure-pages` 의 `static_site_generator: next` 는 basePath를 Next 설정에만 주입하는데,
이 사이트의 이미지 130장은 `src/lib/assets.ts` 가 `NEXT_PUBLIC_BASE_PATH` 를 읽어 주소를
만듭니다. 그래서 두 워크플로 모두 빌드 단계에 아래를 넘겨야 합니다 — 빠지면 이미지가
전부 404입니다.

```yaml
env:
  NEXT_PUBLIC_BASE_PATH: ${{ steps.pages.outputs.base_path }}
  NEXT_PUBLIC_SITE_URL: ${{ steps.pages.outputs.origin }}${{ steps.pages.outputs.base_path }}
```

### 그 밖

- **Vercel / 버킷** — 환경변수 없이 그대로. 루트에서 서빙됩니다.
- `NEXT_PUBLIC_SITE_URL` 은 canonical·OG·JSON-LD 의 절대 URL에 쓰입니다.

## ⚠️ 공개 전 확인

`npm run audit` 이 아래를 매번 보고합니다.

1. **분석(SWOT) 장면의 문구는 데이터에서 도출한 초안입니다.** 채용 담당자가 읽는 자기
   분석이므로 본인 확인 없이 공개하면 안 됩니다. 특히 **위협(T)** 칸은 시장에 대한 주장이라
   데이터에 근거가 없습니다. 다 읽고 `src/data/swot.ts`의 `SWOT_REVIEWED`를 `true`로.

   > 물려받은 초안에서 **수치 두 개를 바로잡았습니다**: 장려상 7 → 실제 6,
   > "2023년 7건 → 2025년 18건" → 실제 13 → 26.

2. **영어 번역이 66개 필드 비어 있습니다** — 전부 프로젝트 35건의 제목·요약입니다.

3. **지원 목표는 현대자동차 로보틱스랩으로 설정되어 있습니다.** 실제 공고는 확인하지
   않았습니다. 바꾸면 `src/data/aim.ts`의 `TARGET`과 `swot.ts`의 O·T 칸을 함께 고쳐야 합니다.
