# 권용현 · HOURGLASS

크롬과 와이어프레임으로 재해석한 모래시계 포트폴리오. **한 화면에서 영화처럼** 재생되는
구조로, 페이지는 스크롤되지 않고 장(chapter)만 전환됩니다.

12장 · 84건의 기록 · 실제 입자 시뮬레이션으로 그려지는 모래시계 ·
그 시뮬레이션을 그대로 읽는 계기판 · 모션 그래픽 문법으로 짠 장면 전환.

```bash
npm install
npm run dev          # http://localhost:3000
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 정적 export → `out/` |
| `npm run verify` | typecheck → lint → 색상 검사 → build → 콘텐츠 감사 |
| `npm test` | 빌드 후 Playwright 77개 테스트 |
| `npm run audit` | 콘텐츠 감사 (번역 누락 · 미검토 문구 · 수치 재검증) |
| `npm run check:css` | 잘못된 색상 리터럴 검사 — 아래 *색상 검사* 참고 |
| `npm run og` | OG 카드 재생성 (`public/og.png`) |
| `npm run images` | 이미지 티어 재생성 — 아래 *이미지 파이프라인* 참고 |

## 유래

원본은 [yhkwon2004/portfolio-hourglass](https://github.com/yhkwon2004/portfolio-hourglass) —
의존성 0개의 단일 `index.html`(1,585줄)이었습니다. 콘텐츠의 더 앞선 출처는
[yhkwon2004/-My-Portfolio_web](https://github.com/yhkwon2004/-My-Portfolio_web) 입니다.

비주얼 언어는 [ALCHE](https://alche.inc)를 레퍼런스로 다시 세웠습니다. 원근 와이어프레임
공간, 화면 밖으로 넘치는 고스트 장명, 모서리 등록 마크, 그리고 **사이트가 자기 상태를 숫자로
읽어주는 계기판**이 그 사이트에서 온 어법입니다.

### 세 번의 변화

**1차 — 구조.** 단일 HTML을 Next.js 16 + TypeScript(strict) + Tailwind v4로 옮기면서
연출의 타이밍과 수치는 전부 보존했습니다.

| 원본 | 지금 |
|---|---|
| 스크립트가 DOM을 만들어서 **크롤러에는 빈 문서** | 12장 전체가 정적 HTML · JSON-LD 포함 |
| 한·영을 **둘 다 DOM에 넣고 CSS로 숨김** | 한 언어만 렌더 · 미번역 필드는 `lang="ko"` 표시 |
| **링크로 특정 장면·기록을 가리킬 수 없음** | `/#projects/project-autonomous` 로 바로 열림 |
| 원본 이미지 **131 MB** 그대로 서빙 | 2티어 사전 렌더 **16 MB** (−88%) |
| 배경 탭에서도 캔버스가 **영구 구동** | 문서가 숨으면 루프 정지 |
| dossier에서 **Tab이 뒤쪽 타일로 새어나감** | 실제 focus trap · 포커스 복원 |
| 벽 타일 35개를 **Tab으로만** 이동 | 방향키 그리드 이동 |

**2차 — 비주얼.** 금색·명조·필름 그레인을 버리고 크롬·모노스페이스·전기 블루로 다시
칠했습니다. 모래시계와 시뮬레이션은 그대로 두고 재질만 바꿨습니다.

**3차 — 모션.** 흐림에서 떠오르기 하나뿐이던 움직임을 모션 그래픽의 어법으로 다시 짰습니다.
컷마다 방향이 있고, 나가는 장에는 퇴장이 있고, 글자·숫자·선·프레임이 각자의 방식으로
등장합니다. 영화처럼 스스로 재생되는 PLAY와, 움직임을 끄는 MOTION 스위치도 생겼습니다.

## 계기판 — 이 사이트의 중심 장치

레퍼런스는 히어로 옆에 `MainLogo Quaternion` 실시간 수치를 띄워, 사이트가 자기 3D 객체의
상태를 스스로 읊게 합니다. 같은 장치를 **이 사이트가 실제로 시뮬레이션하는 것** 위에 올렸습니다.

```
SAND SYSTEM
FLOW   048     공중에 떠 있는 알갱이 수
FILL   0.45    이징된 충전율
TRGT   0.45    수렴 목표 (= 현재 장)
VOL    0.38    높이맵 총합, 구근 기준 정규화
ANG   60.5°    더미가 실제로 안착한 안식각
SRG    0.00    직전 컷 이후 남은 유량 서지
```

**여섯 값 모두 측정값입니다.** 장을 넘기면 FLOW가 치솟고 SRG가 1에서 감쇠하는 것이
보입니다 — 그게 시뮬레이션이지, 돌아가는 가짜 숫자가 아닙니다. 계기판이 거짓말을 하면
장치 자체가 거짓이 되고, 크롬을 두른 거짓말은 크롬이 없는 것보다 나쁩니다.

테스트가 이 점을 직접 검증합니다 (`tests/instrument.spec.ts`): 1초 사이에 최소 한 채널이
바뀌지 않으면 실패하고, 장을 넘겼을 때 TRGT가 커지지 않으면 실패합니다.

## 모션 그래픽

원래 사이트의 움직임은 한 가지였습니다 — 흐림에서 떠오르기. 컷이 일어나면 나가는 장의 내용이
그 자리에서 사라지고, 파란 띠 하나가 빈 화면을 덮었습니다. 나가는 동작도, 방향도, 장과 장
사이의 연속성도 없었습니다.

지금은 After Effects·Cinema 4D에서 쓰는 기법들을 CSS·Canvas·Web Animations API로 옮겨 하나의
어휘로 묶었습니다. 공용 어휘는 `src/styles/motion.css`와 `src/components/motion/`에 있고,
각 장의 스타일시트가 그것을 조합합니다.

### 원칙

| | |
|---|---|
| **방향** | 모든 컷에는 방향이 있습니다. 스테이지가 `--dir`(1 / −1)을 들고, 방향을 타는 키프레임은 전부 이 값을 곱합니다. 뒤로 가기는 두 번째 안무가 아니라 같은 안무의 거울상입니다 |
| **퇴장** | 장은 세 상태를 가집니다 — `live`(등장), `out`(방금 떠난 장의 퇴장), `idle`. 퇴장은 등장을 거꾸로 튼 것이 아니라 따로 짠 동작입니다: 더 빠르고, 가속하고, 진행 방향으로 계속 나아갑니다 |
| **스태거** | 순서는 마크업이 찍는 인덱스(`--i`, `--ci`, `--k`)에서 나오고 스타일시트가 시간으로 바꿉니다. 컴포넌트는 타이밍을 모릅니다 |
| **스프링** | 튀어나오는 것(칩·마크·배지)은 감쇠 진동자를 샘플링한 `linear()` 이징을 씁니다. cubic-bezier는 한 번 넘어갈 수는 있어도 진동하지 못합니다. `linear()`를 모르는 브라우저는 bézier로 폴백 |
| **한 시계** | 스크립트로 도는 트윈(카운터·디코더·타임코드)은 전부 `performance.now()` 하나만 읽습니다. rAF 타임스탬프와 섞으면 두 시계가 어긋나는 순간 타임코드가 −50시간을 읽습니다 — DevTools로 애니메이션을 느리게 돌렸을 때 실제로 그랬습니다 |
| **한 게이트** | 스크립트 모션은 전부 `motion` 한 값을 봅니다 — 동작 줄이기, MOTION 스위치, 첫 프레임 이전에는 꺼짐 |

### 컷의 해부 (앞으로 가기)

| 시점 | 무엇이 |
|---|---|
| 0 ms | 나가는 장: 내용이 위로 빠지며 흐려지고(0.3s), 장 전체가 카메라를 지나치듯 커지며 사라짐(0.46s) |
| 0 ms | 복도가 앞으로 돌진하며 **돌리 줌**(화각이 넓어졌다 돌아옴), 배경 모래가 중심에서 방사형으로 흩어짐 |
| 0 ms | 장 레일의 플레이헤드가 다음 장으로 — 앞쪽 끝이 먼저, 뒤쪽 끝이 90ms 늦게. 늘어났다 줄어드는 follow-through |
| 0–660 ms | 스캔 라인이 화면을 가로지르며 들어오는 장의 번호를 싣고 가고, 간섭선 6개가 진행 방향 순서로 번쩍임 |
| 0–640 ms | 타임코드가 다음 장의 마크로 스크럽 (프레임 필드가 돌아감) |
| 160 ms~ | 고스트 단어가 글자 단위로 진행 방향에서 스윕 — 기울어지고 늘어난 채(모션 블러의 형태로), RGB 분리가 닫히며 고정 |
| 180 ms~ | 슬레이트 번호가 이전 장 번호에서 굴러오고, 장 이름이 디코드 |
| 200 ms | 들어오는 장이 복도 안쪽에서 다가옴 (scale 0.95 → 1) |
| 340 ms~ | 내용이 `--i` 순서로 떠오르고, 숫자는 세어 올라가고, 패널 테두리는 빛이 한 바퀴 그리고, 등록 마크가 스프링으로 모서리에 박힘 |

뒤로 가기는 전부 반대입니다 — 복도가 멀어지고, 모래가 *위로* 솟고(되감기), 내용이 위에서
내려오고, 모래시계가 **예비동작 → 회전 → 오버슈트**로 한 바퀴 뒤집힙니다.

### 기법

| 기법 | 어디에 | 구현 |
|---|---|---|
| 키네틱 타이포 (글자 단위 마스크 리빌) | 이름 · 작업 제목 · 지원 목표 · 연락 카드 | `Kinetic` — 단어마다 clip-path 마스크, 글자가 그 선을 뚫고 올라옴 |
| 디코드 / 스크램블 | 아이브로 · 슬레이트 · 연도 · 계기판 머리 | `Decode` — 실제 텍스트는 그대로 두고, `aria-hidden` 쌍둥이가 그 위에서 스크램블 |
| 카운트 업 | 합계 · 막대 값 · 통계 · 슬레이트 번호 | `CountUp` — React가 만든 텍스트 노드에 직접 쓰고, 끝값은 항상 정확히 |
| 트림 패스 (선 그리기) | 패널 테두리 · 모래시계 외곽선 | 4겹 그라디언트의 `background-size` / SVG `pathLength="1"` |
| 크롬 글린트 | 표제의 이름 | 글자마다 반사 띠가 인덱스만큼 늦게 지나가서, 빛이 이름을 따라 흐름 |
| 스프링 팝 | 칩 · 태그 · 범례 · 배지 · 핍 | `scale` 개별 속성 + `--ease-spring` |
| 스쿼시 & 스트레치 | 원칙 장의 모래알 | 떨어질 때 늘어나고, 닿을 때 눌리고, 튀어 오름 |
| 트래킹 인 | 원칙 장의 축 라벨 | 넓은 자간에서 좁혀 들어옴 |
| 스플릿 리빌 | 분석 장의 4사분면 | 십자의 중심에서 각자의 안쪽 모서리를 축으로 펼쳐지고, 글자가 스플릿 플랩처럼 떨어짐 |
| 폴오프 이펙터 (MoGraph) | 수상 벽 · 작업 눈금 | `useFalloff` — 포인터 거리로 `--fx` 0…1, 스타일시트가 부풀기 · 파형으로 해석 |
| 컨테이너 트랜스폼 | 기록 시트 열기 | 누른 타일의 사각형에서 clip-path로 열리고, 빛의 프레임이 타일에서 시트로 날아감 |
| 멀티플레인 패럴랙스 | 고스트 단어 · 유리 · 워시 · 복도 | 깊이마다 다른 세기로 포인터에 반응 (복도는 시점만 돌림) |
| 타깃 록 레티클 | 누를 수 있는 모든 것 | 포인터를 따라다니다가 컨트롤 위에서 그 경계로 달라붙고 동작 이름을 표시 |
| 마그네틱 버튼 | 단독 컨트롤 | 포인터 쪽으로 최대 7px 기울어짐 |
| 선택 박스 추적 | 수상 벽 | 릴이 넘어갈 때 하이라이트가 깜빡이지 않고 타일 사이를 미끄러짐 |
| CRT 파워온 | 첫 화면 | 빛의 선이 가로로 뻗고, 번쩍인 뒤 화면이 위아래로 갈라져 열림 |
| 러버밴드 | 릴의 양 끝 | 끝에서 더 밀면 장이 살짝 밀렸다 돌아옴 |

### 새로 생긴 기능

- **PLAY** — 한 장을 12초씩 붙잡았다가 다음 장으로 자르며 사이트를 영화처럼 재생합니다.
  타임코드가 원래 장당 12초로 계산되던 가상 수치였기 때문에, 재생 중에는 타임코드가 곧
  재생 헤드입니다 — 매 컷에서 정확히 `장 × 12`에 떨어집니다. 휠 · 키 · 스와이프 · 클릭,
  손이 닿으면 멈춥니다.
- **MOTION 스위치** — 스스로 5초 이상 움직이는 콘텐츠는 페이지 안에서 멈출 수 있어야 한다는
  WCAG 2.2.2를 위한 스위치입니다. 끄면 OS의 동작 줄이기와 *정확히 같은* 사이트가 됩니다.
  OS가 줄이기를 요청했다면 스위치로 다시 켤 수 없습니다. localStorage에 기억됩니다.

### 성능 — 잰 것과 뺀 것

각 장이 등장을 끝낸 뒤의 유휴 프레임률을 소프트웨어 렌더링(헤드리스 Chromium)에서 쟀습니다.
절대값은 GPU가 있는 기기보다 비관적이지만, 원본과의 상대 비교는 유효합니다.

처음 넣었던 연출 셋이 비용의 대부분이었고, 셋 다 뺐습니다.

| 뺀 것 | 잰 차이 | 이유 |
|---|---|---|
| 스캔라인 위를 흐르는 리프레시 바 | 연대기 47 → 60 fps | 불투명도 그룹 안에서 움직여, 전체 화면 레이어를 매 프레임 다시 래스터 |
| 고스트 단어의 느린 표류 | 연대기 47 → 55 fps | 수천 px짜리 레이어를 영원히 매 프레임 다시 합성 |
| (위 둘을 함께) | 작업 25 → 37 · 표제 34 → 48 fps | |
| 작업 판의 블러 · 플레어 입장 | 작업 37 → 40 fps | 3D 판 4장을 릴이 넘어갈 때마다 필터 재계산 |

지금의 유휴 프레임률은 원본과 같은 수준입니다 (대부분의 장 60 fps, 표제 49 · 원본 52,
작업 40 · 원본 41).

같은 작업에서 계기판 샘플(초당 8회)이 **스테이지와 12장 전체를 다시 렌더**하던 것도 고쳤습니다.
샘플은 이제 외부 스토어(`src/lib/store.ts`)로 가고, 다시 그려지는 것은 계기판 하나뿐입니다.

## 모래시계 = 실제 시뮬레이션

CSS 애니메이션이 아니라 매 프레임 계산되는 입자 시뮬레이션입니다
(`src/lib/sim/hourglass.ts`). SVG는 유리 용기만 그립니다.

- 알갱이가 목에서 방출 → 중력 낙하 → 기울어진 벽에 튕김 → 바닥 더미에 착지
- 더미는 84칸 heightmap. **안식각**을 넘으면 옆으로 흘러내려 원뿔이 만들어집니다
- 더미 총 부피가 현재 장으로 수렴 → 모래 높이가 곧 진행도
- 목 부분에 전기 블루 블룸 — 와이어프레임 공간의 빛이 통과하는 것으로 읽힙니다

### 고친 것

**프레임률 종속 (1차).** 원본은 위치를 *프레임당*, 중력을 *초당*으로 적분해서 120 Hz 화면에서
모래가 두 배 빠르게 떨어졌습니다. 전부 초당 단위로 환산했습니다.

**절반부터 흐름이 멈추던 문제 (3차).** 알갱이는 목 바로 아래에서 방출되고, 더미 표면보다
아래에서 생긴 알갱이는 첫 스텝에 착지한 것으로 처리됩니다. 물려받은 안식각이 약 56°였는데
이건 마른 모래가 설 수 없는 경사이고, 더미 원뿔의 꼭대기가 **약 60% 지점에서 목을 넘어섭니다.**
그 뒤로는 새 알갱이가 이미 더미 안에서 태어나 즉시 착지 — 12장 중 5장에서 모래시계가
**완전한 정지 화면**이었습니다.

아무도 몰랐던 이유는 아무도 재지 않았기 때문입니다. 계기판이 FLOW를 찍기 시작하자
사이트 절반에서 `000`이 나왔습니다.

안식각을 마른 모래의 실제 값인 34°로, 충전 계수를 0.74로 내려서 가득 찬 상태에서도 낙하
거리가 남도록 했습니다. 흐름이 채워질수록 가늘어지되 멈추지는 않습니다 — 실제 모래시계와
같습니다. 계기판의 ANG 값도 이제 물리적으로 말이 되는 숫자를 읽습니다.

회귀 테스트가 이 버그를 직접 잡습니다 (`tests/instrument.spec.ts` — "the pour never stalls").
옛 값으로 되돌리면 `chapter 7 (fill 0.63) has no grains in flight`로 실패하는 것을
확인했습니다.

**느린 기기에서 흐름이 멈추던 문제 (4차).** 중력과 방출은 초당 단위였지만, 더미를 안식각으로
붙잡는 슬럼프는 *호출당* 3회였습니다. 프레임률이 떨어지면 슬럼프 사이에 착지하는 알갱이가
늘어 원뿔이 안식각보다 가팔라지고, 80% 남짓에서 꼭대기가 목에 닿아 3차와 똑같이 멈춥니다.
모션 작업 도중 헤드리스 브라우저의 프레임률이 떨어지자 위 회귀 테스트가 이것을 잡았습니다
(`chapter 9 (fill 0.82) has no grains in flight`). 원본 코드도 CPU를 6배 느리게 하면
7 · 9 · 10장에서 FLOW `000`, 안식각 60–77°를 읽습니다 — 느린 기기에서는 원래부터 있던 버그입니다.

시뮬레이션을 고정 1/60초 틱으로 돌리게 바꿔, 더미는 이제 25 Hz에서도 144 Hz에서도 같습니다.
CPU 6배 스로틀에서도 흐름이 멈추지 않는지 확인하는 회귀 테스트를 더했습니다
(`tests/motion.spec.ts` — "the pour never stalls on a slow machine either").

### 06 지표

세 패널 모두 84건의 기록에서 렌더 시점에 집계합니다. **불리한 숫자도 같이 싣습니다** —
"태그 90개 중 69개가 단 1건". 데이터에서 가장 약한 사실이고, 이걸 수상 건수 옆에 놓는 것이
수상 건수를 믿을 이유가 됩니다.

색은 눈대중이 아니라 검증했습니다. 이번 팔레트는 **여섯 검사를 전부 통과**합니다 —
금색 시절에는 단일 색상 2단계 인코딩이라 명도 밴드 검사를 구조적으로 통과할 수 없어
예외를 문서로 남겨야 했는데, 크롬 팔레트는 밴드 안에 채도를 갖춘 두 번째 색상(틸)이
있어서 그럴 필요가 없어졌습니다. 검증 기록은 `src/data/charts.ts` 주석에 있습니다.

수상 등급 색도 같은 검증된 램프에서 나옵니다 — 타일·배지·막대가 전부 한 램프를 씁니다.

## 접근성

- **`prefers-reduced-motion`** — 배경 모래·와이어프레임 복도 루프가 *정지*하고
  (숨기는 게 아니라 루프를 돌리지 않습니다), 켄번즈와 자동재생이 꺼집니다. 파워온 셔터 ·
  레티클 · 스크램블 · 카운트 업도 전부 서지 않습니다. 남는 것은 사용자가 직접 요청한 장면
  전환뿐입니다. 전용 테스트 10개가 이 경로를 검증합니다.
- **MOTION 스위치** — 같은 경로를 OS 설정 없이 페이지 안에서 켜고 끌 수 있습니다 (WCAG 2.2.2).
- **키네틱 타이포** — 글자 단위로 쪼갠 제목은 `aria-label`로 이름을 주고 쪼갠 사본은
  `aria-hidden`입니다 — 스크린리더는 "권, 용, 현"이 아니라 "권용현"을 읽습니다. 문단은 단어
  단위로만 쪼개고 단어를 실제 텍스트로 남깁니다. 어느 쪽이든 `textContent`와 크롤러가 보는
  문장은 원문 그대로입니다.
- **디코더 · 카운터** — 디코더는 실제 텍스트를 건드리지 않고, 카운터는 React가 쓴 문자열로
  정확히 돌아옵니다. 스크립트가 없으면 셔터와 멈춰 둔 키프레임은 `<noscript>` 스타일이
  꺼서, 정적 문서가 그대로 보입니다.
- **키보드** — 벽 타일 35개를 방향키로 이동(열 수는 실제 렌더 기하에서 측정), dossier는
  실제 focus trap + 포커스 복원, 닫힌 시트는 `inert`.
- **스크린리더** — 장이 바뀌면 `aria-live`가 번호와 이름을 읽습니다. 차트에는 같은 숫자를
  담은 실제 `<table>`이 `aria-describedby`로 연결되어 있습니다. 계기판은 `aria-hidden`
  입니다 — 초당 8번 바뀌는 여섯 숫자를 읽어주면 페이지를 쓸 수 없게 됩니다.
- **언어** — 미번역 영어 필드는 한국어를 보여주되 `lang="ko"`를 붙입니다.

## 배포

정적 export이므로 서버가 없습니다. `out/`을 어디에 올려도 동작합니다.

### GitHub Pages

Pages는 켜져 있고, 주소는 https://yhkwon2004.github.io/portfoli/ 입니다.

배포 워크플로가 둘 있습니다. 하는 일이 겹치므로 어느 쪽을 남길지는 정리 대상입니다.

| 파일 | 트리거 | 비고 |
|---|---|---|
| `nextjs.yml` | 이 브랜치에 push | GitHub의 Next.js 샘플. **현재 배포되는 쪽** |
| `deploy.yml` | `main` push · 수동 실행 | 직접 쓴 것. `main` 이 없어 지금은 수동 실행만 |

둘 다 `concurrency: pages` 라 동시에 돌지는 않지만, 같은 사이트를 두 워크플로가 만드는
상태는 오래 두면 어느 빌드가 올라갔는지 알기 어려워집니다.

**하위 경로 주의.** Pages는 프로젝트 사이트를 `/portfoli` 아래에서 서빙합니다.
`configure-pages` 의 `static_site_generator: next` 는 basePath를 Next 설정에만 주입하는데,
이 사이트의 이미지 130장은 `src/lib/assets.ts` 가 `NEXT_PUBLIC_BASE_PATH` 를 읽어 주소를
만듭니다. 그래서 두 워크플로 모두 빌드 단계에 아래를 넘겨야 합니다 — 빠지면 이미지가
전부 404입니다.

```yaml
env:
  NEXT_PUBLIC_BASE_PATH: ${{ steps.pages.outputs.base_path }}
  NEXT_PUBLIC_SITE_URL: ${{ steps.pages.outputs.origin }}${{ steps.pages.outputs.base_path }}
```
